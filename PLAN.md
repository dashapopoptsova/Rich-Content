# План доработки проекта «РИЧ-контент»

Файл отражает текущее состояние и пошаговый порядок разработки.
После каждого шага — коммит в git. Пуш на удалённый репозиторий — только с явного разрешения.

---

## Текущее состояние

### Что реализовано
- `generate_rich.py` — локальный CLI: читает `входные/`, сжимает изображения (Pillow),
  один POST-запрос на OpenRouter, сохраняет результат в `выходные/`
- Retry-логика (3 попытки × 20 сек), обработка ошибок 524/400/timeout/SSL
- SSL-резолюция: truststore → certifi → `SSL_CERT_FILE` → `OPENROUTER_INSECURE_SSL=1`
- Промпт в отдельном `prompt.txt` (5 зон: Hero, Преимущества, Раскрытие, Характеристики, Ассортимент)

### Что не реализовано (требует ТЗ)
- Валидация итогового изображения (ширина кратна строго 800px, длина строга кратна 500px)
- Веб-интерфейс: загрузка файлов (drag & drop), выбор режима
- Режим «Авто» и «Ручной» — сейчас только авто через CLI
- Конструктор блоков: добавить/удалить/переставить, настройки каждого блока
- Предпросмотр результата в браузере
- Экспорт: выбор файлов, формат JPG/PNG
- Шаблоны по категориям товаров
- Возможность встраивания в сторонний сайт

**Важно:** логику сжатия, вызова API и SSL — не копировать, а импортировать
из `generate_rich.py` (вынести в функции с понятными сигнатурами).

### ЭТАП 3 — Режим правок (диалог с моделью на странице результата)
_Цель: после первой генерации пользователь может написать правку текстом,
модель получает только текущий баннер + текст правки и перегенерирует._

**Логика:**
- Главная страница не меняется — одна кнопка «Сгенерировать баннер»
- После генерации на странице результата появляется панель диалога
- Пользователь пишет правку («сделай текст крупнее», «убери таблицу», и т.д.)
- Второй запрос к API: текущий баннер (как изображение) + текст правки → новый баннер
- Исходные фото во второй запрос НЕ передаются
- Итераций может быть сколько угодно (каждый раз — баннер из предыдущего шага)

#### ✅ Шаг 3.1 — Панель правок на странице результата
**Что:** в `templates/result.html` добавить блок под кнопкой скачивания:
- Textarea «Опишите правки...» (placeholder: «Сделай заголовок крупнее», «Убери таблицу размеров»...)
- Кнопка «Применить правки»
**Где:** `templates/result.html`.
**Проверка:** панель отображается под превью баннера, поле ввода доступно.

#### ✅ Шаг 3.2 — Маршрут перегенерации с правками
**Что:** маршрут `POST /refine/<filename>`.
Принимает: `correction` (текст правки от пользователя).
Загружает: только текущий баннер `выходные/<filename>` — как единственное входное изображение.
Формирует промпт: «Это уже готовый РИЧ-баннер. Внеси следующие правки, сохранив общий стиль: {correction}»
Вызывает `run_pipeline([banner_path], prompt_text=refine_prompt)`.
Сохраняет новый баннер в `выходные/`, редиректит на `/result/<new_filename>`.
**Где:** `app.py`.
**Проверка:** ввести правку → открывается новая страница результата с обновлённым баннером.

## Порядок работы

1. Шаги выполняются последовательно в порядке нумерации.
2. После каждого шага — локальный `git commit` с описанием изменения.
3. Перед `git push` (отправкой на удалённый репозиторий) — явное разрешение от пользователя.
4. Перед любым изменением кода — краткое описание «что меняем и зачем», ожидание подтверждения.
